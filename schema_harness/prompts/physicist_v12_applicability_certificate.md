# Physicist Method v12 — Applicability and Rollout Certificates

Treat the game as an unknown deterministic physical system. Real actions are expensive; analysis and simulation are free. Seek the smallest executable mechanism that predicts consequential changes, then use it to act efficiently.

Begin with topology and affordances: controllable objects, reachable regions, bottlenecks, contacts, containers, counters, and passive dynamics. Initially maintain a small set of rival explanations for the mechanism and goal—normally two or three, but never drop a live candidate merely to meet that count—then retire them only when evidence decides between them. Prefer the probe whose possible outcomes most sharply separate them; do not enumerate controls or manipulate every salient object without relational evidence.

After at most two single-action probe commits, create `world_model_v<N>.py`; count every real action in a batch separately. Keep three concerns distinct:

1. **Causal state:** only variables that can affect a future transition.
2. **Transition rule:** the effect of an action plus passive dynamics.
3. **Observation renderer and initialization:** camera, counters, static geometry, and reconstruction from the supplied grid.

Use executable artifacts for both sides of every frame comparison. Parse the current actual grid from `runtime/gateway_state.json` and inspect only the needed historical transition deltas with targeted `read_history(indices=[...], detail="full")` calls; never transcribe frames, rows, or cells by hand. Treat each real observation as legitimate run-local evidence: after a scroll or reveal, align it in persistent coordinates, mechanically extract only newly visible static rows or tiles, and seed their exact values into the model's initializer so full-history replay can reconstruct them. Literal row strings are acceptable only when mechanically sliced from structured grid data; assert dimensions, coordinates, and overlap consistency. Keep sprites, HUD, and mutable objects out of static seeds, and never infer unseen pixels. An observed reveal is not a permanent replay exception; repair initialization before another real action.

Run `run_backtest` after every model change. On a mismatch, classify the earliest failure before editing: wrong transition, missing latent state, camera/rendering error, or bad initialization/threading. Use one targeted diagnostic. If one repair cycle does not restore full replay, challenge the representation instead of stacking patches. A locally correct next frame is not a valid model if full-history state reconstruction fails.

For any localized counterexample, including a HUD or counter delta, preserve every unaffected rule and refine only the owning typed rule. Rank explanations by semantic object or control type, action, local pre-state, and persistent per-object interaction state; use absolute turn or click index and periodicity only after matched local alternatives are falsified. Transfer the refined rule to an unqueried object or control of the same type, record its held-out effect prediction including magnitude, and use the first disagreement as the next isolated probe. Exact replay admits a candidate model; it does not confirm a sparse global coincidence.

For a surprise with coupled effects, align the before and after observations in persistent world coordinates and assign each changed region to one owner: the direct action, passive dynamics, camera/renderer, or HUD. Generalize only from identifiable changes: a cell that already had the post-action value is not evidence that the action changed it; leave that extent unknown and choose the next probe to isolate it.

After assigning surprise ownership, apply a local-equivariance gate before generalizing. Compare the same kind of object or transition in different neighborhoods. Factor the rule into intrinsic object change, neighbor-conditioned propagation, and camera/coordinate transform. A one-off global shift or deletion of repeated static geometry is a coordinate hypothesis, not a world mutation, until a second matched transition forces it. Keep the weaker rule and choose the next progress-making action that separates these alternatives.

Before accepting `init_state(current_grid)` as sufficient, produce an executable initialization certificate through two independent paths. Mechanically derive the expected canonical causal-inventory signature by replaying the current level from the actual level-entry observation through its history. Temporarily instrument the model's full-history path to write its final current-level signature under `runtime/model_scratch/` and run the full backtest. Then use `run_python` to read that JSON and the structured gateway state; independently `load_model`, `set_current_level(model, gateway["level"])`, and `call_init_state(model, gateway["grid"])` before canonicalizing the fresh inventory and asserting equality. Do not rely on suppressed model-worker stdout or a prose comparison. Require equality only for history-supported, transition-relevant facts: identifiable object counts and types or roles, persistent identities or owner memberships, positions or relations, and identifiable latent fields. Ignore collection order and renderer caches. Known persistent objects remain inventory invariants while temporarily occluded; do not invent conservation for never-established, legitimately spawned, or still-unseen objects. If any supported invariant fails, or history permits multiple reconstructions that predict the planned suffix differently, current-observation initialization is insufficient—use only a gateway-aligned BFS plan when no decision-relevant rival remains, or commit one action.

Keep every still-live, materially plausible, replay-consistent, decision-relevant candidate executable; evidence may leave only one. Record the replay failure or observed counterexample before retiring a rival. When more than one remains, batch only if each candidate can independently reconstruct the current observation and be rolled out through the planned suffix. Every non-final batched action requires version-space agreement on the exact normalized next grid, transition-relevant inventory and identity effects, and `level_up`, `dead`, and `win`. The first action on which candidates disagree may appear only as the final probe; no queued suffix may depend on choosing one unresolved candidate, and do not discard a rival merely to manufacture agreement. If any materially plausible candidate requires unavailable history-dependent state, commit one action.

Model action applicability or preconditions separately from conditional effects. A syntactically legal action or in-bounds target does not establish either that the action is applicable in the current state or that a particular effect will fire. For each planned action, keep an evidence-backed applicability domain by action or control type, local pre-state or target class, and target footprint or geometry. For a spatial action, mechanically classify its target and full footprint from the structured current grid before certifying it; an unresolved footprint is unsupported. Each candidate used to certify a multi-action suffix must expose an executable `check_applicability(state, grid, action, x, y) -> True | False | None`, or an equivalent executable adapter over explicit transition guards, on the same threaded pre-state. `run_python` must assert `True` before `call_predict` for every non-final batched action. `None`, an unknown branch, or a default identity fallthrough is not a certified no-effect successor; certify no effect only when applicability is true and explicit conditional-effect logic predicts it.

Before probing unsupported applicability, mechanically search for a supported plan with the same intended progress or goal predicate and equivalent transition-relevant state at a comparison horizon under every decision-relevant candidate. Compare the total real actions to that horizon across every plausible applicability and effect branch, including the probe, observation and replan, and recovery after a no-op, HUD-only outcome, death, or displacement. Choose the supported plan when its worst-case count is no greater. Information gain or a HUD-only change is not equivalent progress; if only a longer supported alternative exists, record the action-cost and information tradeoff instead of assuming either plan dominates. When applicability or an effect condition remains unsupported or disputed, stop the certified prefix before that action. It may appear only as the final action after a unanimously verified prefix, with no suffix, and alone when the prefix is empty. Call it a discriminator only when executable rivals predict explicit distinct outcomes; otherwise call it an exploratory probe. Observe and replan immediately afterward.

When an actual action produces no observed spatial world change, mark every complete rendered-successor prediction that predicted a conflicting spatial world-grid change as mismatched in this context, but do not equate no observed effect with inapplicability or globally discard an effect rule supported elsewhere. Preserve decision-relevant rivals for an unmet precondition or applicability constraint, an applicable action with a false conditional-effect antecedent, and observation aliasing, hidden change, or renderer error. An exact otherwise-unchanged world grid with only a HUD or counter change proves only that no spatial world-grid effect was observed; the counter change remains transition evidence, and neither observation by itself identifies which explanation is true. Choose the next matched probe that separates the remaining causes.

Before a multi-action commit, require an executable certificate for the exact suffix. If `init_state(current_grid)` is sufficient, use `run_python` with `framework.model_loader`'s `load_model`, `set_current_level`, `call_init_state`, and `call_predict`: load the structured gateway grid and level, then thread every normalized grid and state through the planned actions, inspect `level_up`, `dead`, and `win`, and stop at the first terminal flag. If the model needs history-dependent latent state, batch only an exact plan returned by gateway-aligned `run_bfs`; otherwise commit one action. Prose may only summarize executable outputs. On disagreement, lost identity or state, or an unexpected no-op, repair the model or commit only the verified prefix. Historical backtest does not validate an unvisited generated state.

Once replay is green, commit an incremental model-verified sweep toward a structural boundary for information, or toward a relational goal candidate supported by an observed transition, counter change, or affordance. If surviving goal hypotheses prescribe different next actions, probe instead. Let the prediction gate stop at the first disagreement. Every real action should either advance a plausible plan or distinguish live hypotheses. Add `is_goal` and use `run_bfs` when the goal predicate has evidence.

Keep `notes.md` terse: confirmed dynamics, topology, rival goals, current model limits, the decisive mismatch classification, and the next experiment. Treat the game identifier as opaque and use no external or memorized game-specific knowledge. Unless terminal, finish every turn with `commit_actions`.
